# make-knowledge-cards

`make-knowledge-cards` 是一个可复用的 Codex Skill，用于把用户粘贴的文章或本地 `.md` / `.txt` 文件提炼成知识卡片。它优先保留真正重要的知识，合并重复内容，并确保每张卡片只讲一个知识点且不补充原文没有的信息。

默认在原文信息充足时生成 5–8 张卡片；如果重要知识点不足 5 个，会按实际数量输出，不强行凑数。

## 使用方法

Skill 位于 [`skills/make-knowledge-cards`](skills/make-knowledge-cards)。在支持 Skills 的 Codex 环境中调用 `$make-knowledge-cards`，然后提供以下任一种输入：

### 粘贴文章

```text
$make-knowledge-cards
请把下面的文章转换成知识卡片：

缓存把经常访问的数据副本保存在更快的存储层。缓存命中时，
系统直接返回副本。缓存内容可能过期，因此需要删除或更新副本。
```

### 本地文件

```text
Use $make-knowledge-cards to convert C:\notes\cache.md into knowledge cards.
```

当前不支持网页抓取、PDF、Anki 导出或图形界面。遇到网页或 PDF 时，请先把正文粘贴出来，或转换为本地 Markdown/TXT 文件。

## 输入输出示例

**输入：**

```text
哈希表按键保存值。平均情况下，按键查找的时间复杂度是 O(1)。
它需要额外空间保存键值对。
```

**输出：**

```markdown
共生成 2 张卡片。原文只支持 2 个彼此独立的重要知识点，因此不强行补足到 5 张。

## 卡片 1：哈希表按键保存和查找值

- **核心知识：** 哈希表按键保存值，平均情况下按键查找的时间复杂度是 O(1)。
- **简明解释：** 原文把按键作为保存和查找值的依据，并给出了平均查找复杂度。
- **自测问题：** 原文如何描述哈希表的平均按键查找复杂度？

## 卡片 2：哈希表需要额外存储空间

- **核心知识：** 哈希表需要额外空间保存键值对。
- **简明解释：** 原文明确指出，保存键值对需要额外空间。
- **自测问题：** 哈希表的额外空间用于保存什么？
```
